**Authoritative 100-Item Failure Control Matrix & System Invariants Specification**

> This document defines the **known-failure defense system** for Rudrastra.
> **Engineering Principle**: *Production should discover unknown unknowns, not rediscover well-documented e-commerce failure patterns.*

## 0. The 14 Non-Negotiable System Invariants

Every subsystem, database model, API endpoint, background worker, state machine, and administrative workflow MUST preserve these 14 system invariants without exception:

1. **`AUTH_INV` (Authorization Invariant)**: No request may perform an action the actor is not authorized to perform—even if the UI allows or attempts it.
2. **`CAT_INV` (Canonical Catalog Invariant)**: ONE physical component $\rightarrow$ ONE canonical identity (`catalog_products`). Sellers attach offers (`seller_offers`) to canonical products.
3. **`SRCH_INV` (Search Integrity Invariant)**: Search may be incomplete, but it must NEVER be confidently wrong. Exact MPN search must never silently substitute approximate products.
4. **`INV_INV` (Inventory Concurrency Invariant)**: Successful stock reservations $\le$ available sellable inventory at all times (`Sellable = On-Hand - Reserved`).
5. **`CHK_INV` (Checkout Idempotency Invariant)**: Checkout MUST be designed around state machines + idempotency + reconciliation, not HTTP request success/failure.
6. **`PAY_INV` (Payment Reconciliation Invariant)**: Every captured payment MUST eventually reconcile to a confirmed order or an explicit refund.
7. **`LEDG_INV` (Financial Ledger Integrity Invariant)**: Double-entry financial accounting guarantees $\sum(\text{Debits}) == \sum(\text{Credits})$ before seller payout release.
8. **`REF_INV` (Refund Limit Invariant)**: Total refunded amount $\le$ total captured payment amount.
9. **`SLR_INV` (Seller Payout Limit Invariant)**: Released seller payouts $\le$ seller-eligible net balance.
10. **`MKT_INV` (Multi-Seller Aggregation Invariant)**: A parent customer order is an aggregation of independent seller orders; failure in one seller order must not corrupt parent order state.
11. **`AUD_INV` (Privileged Audit Invariant)**: Every privileged state mutation generates an immutable, non-repudiable audit event with actor provenance.
12. **`OPS_INV` (Operational Discoverability Invariant)**: Every unresolved exception is visible operationally; every incident has an assigned owner.
13. **`DIST_INV` (Distributed Event Recovery Invariant)**: Every asynchronous side effect is idempotently recoverable from outbox logs.
14. **`HUM_INV` (Human Mistake Defense Invariant)**: High-risk/dangerous operations require four-person/dual confirmation and explicit confirmation steps.
